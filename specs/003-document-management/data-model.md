# Data Model: Document Management

## Document

Private structured document owned by exactly one authenticated user.

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| `_id` | MongoDB ObjectId | Yes | Generated by the server; immutable |
| `ownerId` | Better Auth user ID | Yes | Taken only from the authoritative session; immutable and never public |
| `title` | String | Yes | Trimmed; empty becomes `Sem título`; maximum 200 Unicode code points |
| `content` | Structured JSON object | Yes | Canonical ProseMirror-compatible document; maximum 1 MB canonical UTF-8 JSON |
| `searchText` | String | Yes | Server-derived from title and visible text; never accepted or returned publicly |
| `version` | Integer | Yes | Starts at 1 and increments once per successful update |
| `createdAt` | Date | Yes | Set once by the server |
| `updatedAt` | Date | Yes | Changes only after successful persisted updates |

### Relationships

- Each document belongs to one Better Auth user through `ownerId`.
- A user may own zero through 500 documents within the validated MVP performance profile.
- Deleting a user is outside this feature; the future account lifecycle must define document handling
  before user deletion is introduced.

### Structured Content

The minimum accepted root is:

```json
{
    "type": "doc",
    "content": []
}
```

The boundary accepts JSON-safe recursive nodes with string `type`, optional attributes, optional child
content and text where structurally valid. It rejects executable values, non-JSON values, prototype
fields, more than 100 levels, more than 10,000 nodes or more than 1,000,000 canonical UTF-8 bytes.
Feature `004-rich-text-editor` owns the final allowlist of node, mark and attribute names.

The root is node 1 at level 1. Every object reached through a node's `content` array adds one node and
one level from its parent. Marks and attribute values count only toward canonical bytes. Attribute
objects reject `__proto__`, `prototype` and `constructor` recursively at every nesting level.

### Search Derivation

`searchText` is rebuilt in the same write that changes title or content:

1. Extract every string-valued node `text` field in document order.
2. Concatenate adjacent text-node siblings and place spaces around nested non-text containers.
3. Prefix the normalized title followed by one space.
4. Apply Unicode NFKD normalization, remove combining marks, lowercase and collapse whitespace.

The query uses the same normalization. Regex metacharacters are escaped before literal substring
matching. Empty normalized input means no search filter.

### Indexes

```javascript
{ ownerId: 1, updatedAt: -1, _id: -1 }
```

This index supports owner isolation, the default order and keyset pagination. No `searchText` index is
created because a non-anchored substring regex cannot use it as a text range. Index creation is an
explicit deployment step; production does not use automatic index synchronization.

### Invariants

- The client cannot set or change `_id`, `ownerId`, `searchText`, `version`, `createdAt` or `updatedAt`.
- Every read and mutation filters by both `_id` and the session-derived `ownerId` when addressing one
  document.
- List and search never return `content`, `ownerId` or `searchText`.
- A failed validation, stale version or persistence operation changes no persisted field.
- A successful update increments `version` exactly once and advances `updatedAt`.
- A successful delete physically removes the record before the API returns `204`.

### State Transitions

```text
Absent
  | create(owner from session, valid input)
  v
Persisted(version=1)
  | update(expectedVersion=current, valid input)
  v
Persisted(version=current+1)
  | delete(owner from session)
  v
Absent
```

Rejected transitions:

- `update(expectedVersion != current)` returns `412 DOCUMENT_VERSION_CONFLICT` and preserves both the
  current record and the caller's local draft.
- Any operation with no owner-scoped match returns `404 DOCUMENT_NOT_FOUND`, whether the ID is invalid,
  missing, deleted or belongs to another user.
- Creation or update beyond title, content, depth or node limits returns a stable validation error and
  makes no persistence change.

## Document List Item

Read projection used by list and search responses.

| Field | Type | Rules |
|-------|------|-------|
| `id` | String | Public representation of `_id` |
| `title` | String | Persisted normalized title |
| `version` | Integer | Current persisted version |
| `createdAt` | ISO 8601 string | Creation time |
| `updatedAt` | ISO 8601 string | Last successful update time |

Items are ordered by `updatedAt DESC, id DESC` for both unfiltered and searched pages.

## Document Cursor

Opaque transport value for keyset pagination. Its internal signed payload contains:

| Field | Type | Rules |
|-------|------|-------|
| `v` | Literal `1` | Cursor format version |
| `updatedAt` | ISO 8601 string | Last item sort timestamp |
| `id` | ObjectId string | Last item tie-breaker |
| `ownerFingerprint` | String | HMAC-derived binding to the authenticated owner |
| `searchFingerprint` | String | Digest of normalized search criteria |
| `limit` | Integer | Page size from 1 through 50 |

The API authenticates the cursor with HMAC using an environment secret. Invalid, altered or mismatched
cursors return `400 INVALID_CURSOR`. The payload is an implementation detail and is never a client
contract.

## Client Draft State

Transient web state; it is not persisted separately by this feature.

| Field | Type | Rules |
|-------|------|-------|
| `snapshot` | Document response | Last confirmed server state and ETag |
| `draftTitle` | String | Current local title input |
| `draftContent` | Structured JSON | Current local content |
| `saveState` | Enum | `idle`, `saving`, `saved`, `validation-error`, `conflict`, `persistence-error` |
| `problem` | Problem or null | Last actionable failure without document payload |

Only a successful response replaces `snapshot` and clears the corresponding pending state. Conflict,
validation, network and persistence errors retain both draft fields.
